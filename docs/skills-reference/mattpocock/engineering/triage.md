# Triage

> **Sumber:** [`skills/engineering/triage/SKILL.md`](https://github.com/mattpocock/skills/blob/main/skills/engineering/triage/SKILL.md)
> **Repo:** mattpocock-skills
> **Bucket:** engineering

## Mengapa skill ini penting

Issue tracker tanpa state machine cepat menjadi tumpukan tak terurus. Skill `triage` menerapkan state machine eksplisit dengan **dua kategori** (`bug` / `enhancement`) dan **lima state** (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`). Setiap triage step menulis komentar ber-disclaimer `> *This was generated by AI during triage.*`, agar penerima tahu konteksnya.

Skill juga sengaja menumbuhkan basis pengetahuan `.out-of-scope/` (untuk feature yang ditolak permanen) sehingga rejection ke depan tidak harus mengulang argumen yang sama.

## Kapan menggunakannya

- User ingin create issue, triage incoming bug/feature, prepare issue untuk AFK agent, atau mengelola workflow issue.
- Maintainer "show me what needs attention" / "let's look at #42" / "move #42 to ready-for-agent".
- Prasyarat: `setup-matt-pocock-skills` agar label mapping & issue tracker terkonfigurasi.

## Cara menggunakannya

1. **Setiap komentar / issue baru harus diawali disclaimer AI** (template di SKILL.md).
2. **Show what needs attention**: query tracker, present tiga bucket oldest-first — Unlabeled, `needs-triage`, dan `needs-info` dengan aktivitas reporter sejak triage notes terakhir. Tampilkan count + one-line summary.
3. **Triage issue spesifik**:
   - Gather context: full issue body + comments + label + reporter + dates; parse prior triage notes; explore codebase pakai glossarium; baca `.out-of-scope/*.md` untuk surface prior rejection serupa.
   - Recommend kategori + state dengan reasoning + codebase summary. Tunggu maintainer.
   - **Reproduce (bugs only)** sebelum grilling apa pun: baca steps, trace kode, run command/test. Repro sukses = agent brief jauh lebih kuat.
   - Grill bila perlu fleshing out (jalankan `grill-with-docs`).
   - Apply outcome: `ready-for-agent` → post agent brief; `ready-for-human` → struktur sama + alasan undelegable; `needs-info` → triage notes (template); `wontfix` bug → polite explanation + close; `wontfix` enhancement → tulis ke `.out-of-scope/` + link + close.
4. **Quick state override**: bila maintainer bilang "move #42 to ready-for-agent", percaya — apply role langsung, konfirmasi action, lalu lakukan. Skip grilling. Bila pindah ke ready-for-agent tanpa grilling, tanyakan apakah perlu agent brief.
5. **Resume previous session**: bila ada prior triage notes, baca, cek apakah reporter sudah menjawab pertanyaan; jangan re-ask yang sudah resolved.

## Contoh / Studi kasus

Issue #87 baru: "Aplikasi crash ketika filter date range dipakai dengan timezone non-UTC". State: unlabeled. Agent: kategori = `bug`, state recommendation = `needs-triage` dulu (perlu repro). Maintainer setuju. Agent reproduce: jalankan test dengan `TZ=Asia/Jakarta` → memang crash dengan error `Invalid Date`. Agent surface ke `.out-of-scope/`: tidak ada match. Karena repro sukses + jelas, agent recommend pindah ke `ready-for-agent` dan post agent brief (mengikuti `AGENT-BRIEF.md`) yang menjelaskan reproduksi, area kode (pakai glossarium domain — "DateRangeFilter module"), acceptance criteria, dan link ke ADR-0009 tentang timezone handling. Issue siap dipick agent.

Issue #88: "Add CRM integration". Agent menemukan `.out-of-scope/crm-integration.md` dari 6 bulan lalu — alasan: bukan core value prop, butuh investasi besar. Agent surface ke maintainer; maintainer setuju keep wontfix. Agent post komentar link ke file lalu close.

## Kesimpulan

Skill ini adalah "router" issue. Tegakkan disclaimer AI, gunakan label mapping yang sudah dikonfigurasi, dan reproduce sebelum grill untuk bug. Pasangkan dengan `to-issues` (untuk pecah work besar) dan `to-prd` (untuk plan baru).
